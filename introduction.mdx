Sheet JSON is a data format and SDK that represents spreadsheet workbooks as structured, typed JSON. Instead of opaque binary formats, every workbook, sheet, table, and list is expressed as a plain JSON object with a predictable shape — making workbook data portable across languages, services, and automation pipelines without any proprietary parsing.

## Why Sheet JSON?

Spreadsheet data powers a huge amount of business logic — trade books, payment reports, configuration tables — but moving that data between systems is historically painful. Sheet JSON addresses four core problems:

- **Data Portability** — JSON is lightweight and language-independent. Workbook data represented as JSON can be shared, exported, or transformed across any platform that can read a string.
- **Interoperability** — Applications and APIs that need to handle spreadsheet data programmatically can consume Sheet JSON directly, regardless of the language they are written in.
- **Automation** — Complex data structures such as large trade books or reconciliation reports can be merged, filtered, and transformed in code without touching a spreadsheet editor.
- **Standardized Structure** — Headers, rows, sheet names, and block discriminators are all clearly defined fields in a shared schema, so every consumer knows exactly where to look.

## Data Model

Sheet JSON uses a three-level hierarchy. A **Workbook** is the top-level container. Each workbook holds one or more **Sheets**. Each sheet holds one or more **Blocks**, and every block is either a **Table** or a **List**.

| Level | Type | Contains |
|-------|------|----------|
| 1 | `Workbook` | One or more `Sheet` objects |
| 2 | `Sheet` | One or more `Block` objects (`Table` or `List`) |
| 3 | `Table` | A `header` array and a `rows` array of arrays |
| 3 | `List` | An `items` array of single-key objects |

A table header is an array of column names. Each row is an array of values positionally aligned to that header — `rows[n][i]` belongs to `header[i]`. Use `null` for an empty cell. A list stores key-value pairs as single-property objects, such as `{"currency": "INR"}`.

<Note>
  Every workbook, sheet, and block carries an `@entity` field that acts as a
  type discriminator. The deserializer uses this field to decide which class to
  instantiate — `"workbook"`, `"sheet"`, `"table"`, or `"list"`. Always include
  `@entity` when constructing or transmitting Sheet JSON payloads.
</Note>

Here is a complete workbook with a payment table and a settings list:

```json
{
  "@entity": "workbook",
  "name": "report_workbook",
  "sheets": [
    {
      "@entity": "sheet",
      "name": "summary_sheet",
      "blocks": [
        {
          "@entity": "table",
          "name": "payment_table",
          "header": ["reference", "amount"],
          "rows": [["PAY-1", 150]]
        },
        {
          "@entity": "list",
          "name": "settings_list",
          "items": [{"currency": "INR"}]
        }
      ]
    }
  ]
}
```

The value `150` belongs to the `amount` column because both are at index `1` in their respective arrays. The settings list holds the key `currency` with the value `INR`.
